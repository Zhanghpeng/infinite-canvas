# 系统素材库（姿势 / 服饰 / 脸型 / 二次元）

侧栏「素材 → 系统预设」原来只有一套姿势图集（288 组，5 机位线稿）。现在改成一个统一的
多库浏览器：**服饰 · 姿势 · 脸型 · 二次元** 四个库共用同一套检索、筛选与插入交互。

外部数据来自 [Deeyu/ai-costume-gallery-zh](https://github.com/Deeyu/ai-costume-gallery-zh)
（中文索引 + 作者自建 Cloudflare Pages 图片镜像）。**仓库里不落任何图片和上游索引**，
运行时拉取 + IndexedDB 缓存，理由见文末「版权与体积」。

## 一、四个库的事实

| 库 | 条目 | 一张素材 = | 索引体积 | 图片档位（实际使用） |
|---|---|---|---|---|
| 服饰 | 1,407 | 1 张平铺图（2:3，无人物） | 807 KB | 缩略图 7 KB / 预览图 41–93 KB（**插入用预览图**） |
| 姿势 | 233 组 | 5 机位线稿 | 本地打包 | 单档 PNG ~267 KB |
| 脸型 | 1,499 | 1 张正面脸图或造型参考（4:5） | 957 KB | 缩略图 12 KB / 原图 1.8 MB（**插入用原图**） |
| 二次元 | 843 条目 | 彩图 ± 发色变体 / 线稿 | 656 KB | 缩略图 / 原图 ~189 KB / 线稿 ~40 KB |

几个和交互强相关的特性：

- **服饰有关键词**：每条 10 个中文词 + 一串英文词（共 86 个中文词）。中文词能当筛选维度，
  英文词能直接贴进提示词——这是服饰库相对姿势库最大的增量价值。
- **脸型只有两档图**：没有中间尺寸，所以脸型卡片不做「悬停换大图」。
- **二次元有变体**：46 个发型各有 5 个发色变体（1,027 行 → 843 条），姿势条目额外带线稿。
- **深度图和姿势同 id**：`ai-pose-depth-gallery.pages.dev/{thumbs|img}/{组ID}_{视角}`，
  所以「深度图」是姿势卡片上的一个开关，不需要单独拉 1 MB 的 depth 索引。

## 二、数据层

```
web/src/lib/canvas/system-library/
├── types.ts          # LibraryItem / LibraryVariant / FacetGroup
├── sources.ts        # 四个库的取数、字段归一化、IDB 优先加载
├── facet-map.ts      # 服饰 86 个关键词 → 六个分面组
├── query.ts          # 分词检索、分面过滤、分面计数
├── cache.ts          # IndexedDB，7 天过期
└── memory.ts         # 收藏 / 最近使用（localStorage）
```

所有库在 `sources.ts` 里归一化成同一个 `LibraryItem`：

```ts
{
    key, library, id, title, meta, tags, terms,
    thumb, preview, image,          // 列表 / 悬停 / 插入 三种用途分开
    variants: [{ key, label, short?, swatch?, thumb, image, altThumb?, altImage? }],
    facets: { 组键: [取值] },
    search: "小写检索串",
    altThumb?, altPreview?, altImage?   // 服饰的二次元画风镜像
}
```

- `variants` 首项就是默认视图；姿势的 5 个机位、二次元的 5 个发色、线稿都在这里。
- `altThumb / altImage` 是"第二形态"：姿势指深度图，服饰指二次元画风。卡片上统一处理，
  不需要在 UI 里判断是哪个库。
- 服饰标题取「品类 · 颜色 · 材质」（如 `半身裙 · 大衣 · 象牙白`），比按原始顺序取前三个词更好认。

## 三、检索与分面规则

- **自由词**：按空格分词，全部命中才算（AND），扫描 `编号 + 分类 + 中英文关键词`。
- **分面**：组内「或」、组间「且」。
- **计数排除本组**：给某个组算计数时忽略该组已选值，否则组内多选后其余项全归零、点不动。
- **0 计数置灰**：chip 上显示实时数量，数量为 0 且未选中时禁用——避免点进去才发现空。
- 服饰的六个分面组：`季节 / 品类 / 颜色 / 材质 / 版型 / 配件`；86 个关键词的分组写死在
  `facet-map.ts`，`__tests__/query.test.ts` 断言其条目数与分组合法性。

侧栏只有 220–480px，**分面默认全部收起**，只留一行组名 chip，点开一组才铺取值；
否则六组 chip 会把首屏卡片全挤到折叠线以下。

## 四、交互决定

| 操作 | 结果 | 理由 |
|---|---|---|
| 点卡片 | 插入画布成图片节点 | 与旧姿势卡一致，沿用肌肉记忆 |
| 拖卡片 | 在落点创建节点 | 同旧行为 |
| 卡片右上 `★` | 收藏（本地） | 分镜要角色一致性，同一件会反复取用 |
| 卡片右上 `⧉` | 复制英文关键词 | 服饰/二次元的词可直接进提示词 |
| 卡片右上 `↑` | 插入并**连到当前选中节点**作为参考图 | 比"插节点再连线"少两步 |
| 点卡片上的关键词 | 追加进搜索框 | 关键词本身就是标签 |
| 变体胶囊/色点 | 切换机位、发色、线稿 ↔ 彩图 | 一个条目一张卡，不把变体铺成独立卡 |
| 滚到底 | 自动加载下一批 48 条 | 1,407 条不能一次渲染 |

- **悬停 300 ms 换预览图**：列表用 7 KB 缩略图，悬停才加载 41–93 KB 预览图。
- 图库切换时清空筛选、保留搜索词（"同一句话换个库再看看"）。
- 收藏与最近使用只存 `library:id` 键，不存图片。
- 三个出口按钮**常显半透明**（hover 到 100%）：只在 hover 出现的话，触屏用户和没试过悬停的人
  根本发现不了收藏/复制/连参考图这三个动作。

## 五、插入落位与连线

插入不走"居中叠放"，落位与连线都由画布侧统一处理：

| 场景 | 落位 | 代码 |
|---|---|---|
| 点卡片（无选中） | 视口正中；被占则向右排、再向下排，放不下退回 48px 阶梯错位 | `findStaggeredPosition` |
| 点 `↑`（有选中） | 贴到目标节点**左侧**，左侧被占依次试右/上/下 | `findBesidePosition` |
| 拖到画布 | 落在鼠标位置（`targetPosition` 优先） | `handleAssetInsert` |

三条硬性约束：

1. **候选位置夹在可见区内**，且可见区左边界要扣掉侧栏宽度（侧栏是浮层，容器 rect 从屏幕左边起算，
   否则节点会插到侧栏底下）。节点比视口还大时只要求"露出一块能看见的部分"。
2. **参考图连线必须走 `normalizeConnection`**：直接 push 一条 `{fromNodeId,toNodeId}` 会绕过
   重复连线、媒体类型、参考位配额校验，画布上会出现红线或超额参考。被拒时给 toast 提示。
3. **节点图片一律用本地副本的地址**（`uploadImage` 的 objectURL / `storageKey` 直链），
   回落成上游 CDN 直链会让画布内容依赖外网，离线就是空图。素材字节此时已经落盘，没有必要再用外链。

## 六、加载与缓存

- 索引统一从 `deeyu.github.io/ai-costume-gallery-zh/...` 取（带 `access-control-allow-origin: *`）。
- 归一化结果写 IndexedDB（`infinite-canvas-system-library` / `indexes`），键 `syslib:v2:<库>`，
  7 天过期；同一库的并发请求共享一次加载；隐私模式或配额不足时静默降级为纯内存。
- 失败不写缓存，面板给「重试」按钮。
- 加载中显示 6 个骨架块，不用转圈。

## 七、版权与体积（为什么不在仓库里打包）

上游 README 明确：**程序代码 MIT，但图片、原始数据及基于其整理的中文数据不适用 MIT**，
且多数原站禁止再分发。全量图片约 1.42 GB，其中写实服饰的原图 PNG 也不在 Pages 发布目录里。
因此本项目只做"运行时取数 + 本地缓存"，不 vendor 索引、不镜像图片。

## 八、新增一个库要改什么

1. `types.ts` 的 `SystemLibraryId` 加一项；
2. `sources.ts` 加一个 `loadXxx()` 并归一到 `LibraryItem`，在 `buildLibrary` 里分支；
3. `SYSTEM_LIBRARY_FACETS` 给它定义分面组（组键 → i18n 后缀）；
4. `SYSTEM_LIBRARY_TOTALS` 给静态总量（或像姿势一样走 `getSystemLibraryTotal`）；
5. 面板 `LIBRARY_ORDER` / `LIBRARY_ASPECT` 各加一行；
6. i18n 补 `canvas.systemLibrary.libraries.<id>` 与新增分面组文案。

## 九、已知限制

- **写实服饰只用预览图**：原图 PNG 不在 Pages（需从 GitHub 取，国内基本不可达）；
  预览图 webp 41–93 KB，做参考图够用。
- **没有 CDN 降级**：四个镜像同时不可用时只能等恢复或重试，未做备用域名轮换。
- **`asset-picker-modal` 仍是旧的两页签**（我的素材 / 姿势预设），未接新库；
  弹窗场景直接用系统素材的需求还没出现。
- **不支持多选批量插入**（做一套 look 要连点三张），也未做"服装 + 姿势"组合插入。
- **视口装不下第二张时参考图会叠 48px**：素材图 427×640，1080 宽的画布只放得下一张；
  此时只能靠错位 + 自动选中提示"又插了一张"，缩放画布后才排得开。
- **"最近/收藏"按库过滤**：切到另一个库看不到别的库的记录（键含库前缀），空态有专门文案。
- 二次元"表情/眼睛/发饰"等条目没有变体，与服装、姿势混在同一列表里，靠分面区分。
