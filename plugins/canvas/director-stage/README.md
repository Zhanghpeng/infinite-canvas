# 3D 导演台（director-stage）

画布节点插件：在一个大窗口里**摆人物与道具、调机位**，然后把「谁在哪、和谁什么关系、镜头怎么走」导出成画布上可以直接用的产物。

它不做建模。要精细模型就在 Blender 里做好、导出 `glb` 再导入进来当主体或背景元素。

## 交互形态（v0.2.0 起）

- **卡片只做「预览 + 入口」**：双击卡片（或点卡片上的「打开导演台」、或悬停工具条的「导演台」）打开**大窗口导演台**。
- **大窗口里编辑**：左侧大视口（拖空白 = 转视角、拖人物 = 地面移动、滚轮 = 焦距、双击空白 = 适应全部），右侧固定侧栏（人物与道具 / 机位 / 导出）。
- 关闭大窗口时自动留一张 360p 预览图给卡片，并 flush 状态（关掉即保存）。
- 设计取舍：3D 视口不常驻节点卡片 —— 卡片又小又和「拖动节点」抢手势，而且每个节点常驻一个 WebGL 上下文会顶到浏览器上限。只有大窗口打开期间才存在视口，关闭即 `forceContextLoss` 释放。

## 人物走位（blocking）

选中一个物体后，用它的「**记录走位点**」按顺序记位置与朝向（可以给每个点设停留、可删、可清空）——和「记录当前机位」是同一套心智。**两个以上走位点就会动**：走过去、停下、转身。

- **与镜头共用同一条时间轴**（这是设计红线）：同一个运镜时长、同一套「行程 = max(200ms, 时长 − Σ停留)，均分各段」公式，所以播放时人动与镜头动天然对齐；导出的 mp4 里人物也在动；首/尾帧导出按 `t=0` 与 `t=整段结束` 渲染，于是**首帧就是走位起点、尾帧是终点**。
- 总时长取「相机时间轴」与「各走位时间轴」里最长的那个（不短于你设的运镜时长）。
- **提示词里的「表演」段**按时间段说清谁在什么时候走到哪、转向谁（见上）。
- **地面上的走位路径**（折线 + 落点 + 朝向箭头）会画出来，选中那条是蓝色；**出画预警**会在运镜预演区提示「第 2.3s 起『女主』横向出画」。
- 走位只改位置与朝向，**不含姿态动画**（灰模没有骨骼）；要真正的动作需要导入带动画的 glb。
- 排查：打开带 `track` 的场景却看不到「人物走位」提示 / 人物不动 → 页面跑的可能是旧版插件（旧版不认识 `track`，保存时还会把它抹掉），**强制刷新**再连一次本地 Agent；大窗口标题旁与本节点卡片右下角都有版本号。

## 素材库与「我的模板」（自己做的素材有地方放）

导入过的 glb 会自动进**「我的素材」**：插件级、跨节点共享 —— 之后**任何**导演台节点都能在素材下拉里直接选用它，不用再导一遍。

- **不重复占存储**：同一个文件（同名同大小）再导入时自动复用库里那份；同一个素材摆多个物体，也只解析/上传一次（按素材 id 缓存 + clone）。
- **改名 / 删除**：选中「我的素材」里的条目就能改名；删除前会扫画布上**有几个物体在用它**并提示后果（删物体**不会**再连带删掉素材字节 —— 字节归素材库所有）。
- **备份**：「导出素材库」把自己做的素材存成一个 JSON，「导入素材库」按 id 只补不覆盖 —— 换机器 / 清浏览器之前先导一份。
- 素材存在**本机**（插件私有存储 / IndexedDB），不上传、也不随工程走；素材库总量超 200MB 会在导入时提醒。

**「我的模板」**：场景模板区多了「存为我的模板」—— 把当前场景（物体 / 机位 / **人物走位 / 导入的模型** / 运镜 / 灯光）存成自己的模板，和内置模板一样**两段确认**套用、可改名/删除（上限 20 个）。

- 模板清单会同步到节点 metadata 的 `stageTemplateIds`，所以 **Agent 与「预演搭建」技能可以按 id 直接套用你的模板**（`canvas_director_stage` 的 `sceneId` 先查内置、再查我的模板）。

## 背景板（把生成的画面回填成场景背景）

「素材」区多了**背景板**：从画布上选一张**已生成的图**（通常是环境/空镜），把它当作 3D 场景的背景 —— 灰模人偶就合成在真画面里，导出的参考图 / 首尾帧 / 多视图 / 运镜视频**都吃这张底图**。这是「预演（灰模摆位）→ 实拍（生成画面）→ 合成（人落在真画面里）」的闭环。

- **活链，不是拷贝**：只记图片节点的 id —— **那张图重新生成后，背景板自动跟着更新**。
- **隐藏环境类素材**（默认开）：背景板打开时，房间/街道地块这类环境占位不再渲染 —— 它们只是占位，真环境就是这张图。物体仍在列表里、仍可选中与拖动（只影响渲染与导出）。
- **图还没生成出来时不会静默**：下拉里标「（还没有画面）」，状态行与「运镜预演」区的自检都会提醒 —— 否则你会导出一张没有环境底图的画面。
- **怎么用**：先生成/导入一张环境图 → 大窗口「背景板」下拉选它 → 「设为背景板」→ 摆人 → 导出。
- 已知限制：背景板按视口**铺满**（three 的贴图背景是拉伸铺满），所以 **16:9 的图配 16:9 的导出最匹配**，非 16:9 会拉伸；另外这是"背景"而不是"相机匹配"，3D 机位与这张图的透视（地平线）对齐需要你自己调机位（或后面加专门的"对齐地平线"工具）。
- Agent / 技能：`canvas_director_stage` 传 `backdropNodeId`（+`backdropHideEnvironment`）即可 —— 「生成环境图 → 建导演台 → 设背景板 → 摆人 → 导出」可以全自动。

## 场景模板（一键搭好整套）

侧栏最上面的「场景模板」是**一整套可直接拍的东西**：环境 + 人物 + 道具 + 当前机位 + 关键帧机位 + 运镜 + 灯光，参数参考真实拍法。选好点「套用模板」——因为会**替换当前节点的物体/机位/灯光**，所以是**两段确认**（第一次点变成「确认套用」），导出格式与语言会保留。

| 分组 | 模板（拍法） |
| --- | --- |
| 对话 | 双人对话 · 过肩正反打（OTS 正反打 50mm）· 双人对话 · 外反打（85mm 留视线空间）· 群像 · 横扫 |
| 单人 | 单人独白 · 推近特写（50→85mm dolly-in）· 英雄镜头 · 低角度上摇（28mm + 摇臂） |
| 动作 | 横移跟拍 · 街头 · 雨夜对峙 · 低机位推近 |
| 风景 | 天台远眺 · 摇臂拉起 · 海边远眺 · 缓推 |
| 静物 | 静物产品 · 环绕（180°） |

## 摄影灯光（白天 / 夜晚 / 室内 / 逆光）

真实拍摄里光常常比机位更决定画面，所以给了四档氛围级预设（主光方向/强度/色温 + 补光 + 环境光 + 背景色）：**白天 / 夜晚 / 室内 / 逆光**。切一下就能看出是日戏还是夜戏，导出的参考图吃的是同一套灯。模板会带上它自己的灯光（比如「雨夜对峙」用夜晚、「海边远眺」用逆光）。

## 内置素材库

「人物与道具」区的下拉按 **人物 / 道具 / 环境** 分组，选好点 **「+ 添加」** 直接落到地面（环境类落在原点，方便人物站进去）：

| 分组 | 素材 |
| --- | --- |
| 人物 | 成年男、成年女、儿童、坐姿人物 |
| 家具 | 桌子、椅子、沙发、床、书桌、书架、地毯、窗帘、台灯、电视、吧台、盆栽、衣柜、纸箱 |
| 街道 | 路灯、长椅、栏杆、公交站牌、售货机、店招、汽车、自行车、石头 |
| 户外 | 树、帐篷、篝火、门框、柱子 |
| 环境 | 房间（6m）、街道（10m）、天台（9m）、公园（14m）、海边（14m）、地形地块（12m）、远景楼群 |

- 全部是**灰模**（用图元拼出来的色块，程序化生成，不依赖任何外部模型文件），定位是搭关系、定构图；要好看的画面还是走 Blender 出图或模型生成。
- 素材的**高度与占地是从部件算出来的**（`assetHeight` / `assetRadius`），提示词里的「约占画面高度」用的就是真实高度，不会和造型脱节。
- **环境类不当作主体**：提示词里单独一行（`环境：房间（6m）`），不参与「关系」「构图」两段（否则会写出「房间面向镜头」这种噪音），也不画接地阴影。
- 想加素材：在 `src/library.ts` 的 `BUILTIN_ASSETS` 里加一条部件数据即可，不用写建模代码。

## 场景里的相机元素

大窗口里每个关键帧机位都会在场景中摆一台**小相机**（机身 + 镜头 + 取景锥 + 名字标签，标签就是「1 过肩」这样的编号+名称），**当前机位**单独一台蓝色、标「当前机位」。所以：

- 一眼能看出镜头在哪、朝哪，以及每个机位的**取景范围**（取景锥的角度跟着焦距走：焦距越短锥体越宽）——不用在脑子里换算方位角。
- 机位一多也不会混：编号标签和右侧列表是一一对应的。
- 取景锥按参考图的 16:9 画，和实际导出画面一致。
- **看不到自己的相机是正常的**：视口就是「从当前机位往外看」，所以「当前机位」那台相机正好在你脚下。点机位区的 **「看全场（自由视角）」** 就切到外部俯视视角（把最远的物体与所有机位都框进来），这时能看到**所有**相机元素与取景锥；在自由视角里转视角只是看，**不会改动机位**，点「回到当前机位」回到自己的镜头。
- **可见性规则**：相机元素与选中高亮只在**编辑视口**里出现；**播放运镜**、**导出**（参考图 / 首尾帧 / 多视图 / 运镜视频）时全部隐藏 —— 播放就是看成片，导出画面里飘着相机方块会被模型当成真实物体。
- **怎么抓住相机**：每个相机元素带一个看不见的 1.5m 命中体，鼠标移上去会变手型；按住时机身与取景锥变蓝、右侧机位列表对应行高亮、状态行会说明当前操作。
- **点相机元素 = 选中它 + 站到外面看全场，不会把你送进那台相机里**（布局与调机位需要上帝视角；之前点一下就会"钻进相机"，已经改掉）。想真的把镜头切到那台机位，点列表行里的 **「切到」**。
- **改机位三种方式**：① 直接拖场景里的相机元素（地面拖，只改方位角与距离，高度角/焦距/视线高度不变）；② 选中它后在右侧用滑块改；③ 点「切到」把它当镜头 → 调好 → 点列表里的「覆盖」。
- **流畅度**：拖拽时只更新被拖的那一个物体；拖拽/播放期间自动降一档渲染质量（像素比 1.5 → 1），结束恢复；**导出始终强制 1:1**（Retina 上不会被放大成两倍，运镜视频的帧尺寸也一定与编码配置一致）。

## 运镜预演

「机位」区就是**关键帧列表**（最多 8 个）：摆好一个机位点「+ 记录当前机位」，随时可以「覆盖」成当前机位、改名、删掉，还能给每个机位设**停留时长**（0 / 0.5 / 1 / 2 秒）。

在「运镜预演」里选好时长与缓动，点 **▶ 播放运镜**，视口就会按时间轴连续演出整段运镜（方位角/仰角/距离/视线高度/焦距一起插值），下面是进度条与这段运镜的文字描述（就是导出提示词里那段）。

- **时间轴**：`总时长 = Σ停留 + 行程`，`行程 = max(200ms, 时长 − Σ停留)` 平均分给各段。也就是说「停 1 秒再摇过去」就是被压缩出 1 秒停留的结果。
- 时长可选 1.5 / 2 / 3 / 5 / 8 秒，缓动「缓入缓出 / 匀速」对整段生效；`fps` 用于逐帧导出（预演按屏幕刷新率走）。
- **预演不改状态**：播放期间相机只是临时动画，停止后回到保存的机位；播放中动任何控件会立即停止预演。
- 运镜描述会按段串起来：`运镜：先推近（dolly-in），最后镜头抬高（crane up）；全程约 4.0s，每个机位停留约 0.5s，节奏缓慢均匀。`
- 已知限制：方位角走**最短弧**，所以两个机位相差 350° 只会转 10°；想表达超过半圈的大环绕需要中间多插一个机位（或后面再加「环绕圈数/方向」）。

### 导出运镜视频（mp4）

同一区块里两个按钮：

| 按钮 | 做什么 |
| --- | --- |
| 导出运镜视频 → 视频节点 | 把 A→B 这段运镜逐帧渲染并编码，**落成一个画布视频节点**；若导演台下游有视频节点，顺手接上 —— 宿主会按节点类型把它归为参考视频（`ref_video_01`），后续「全能参考视频」生成就能用它 |
| 下载视频 | 直接下载文件，不落节点 |

- **编码优先级**：先试 `WebCodecs`（`VideoEncoder` + H.264）配 `mp4-muxer` 产**真 .mp4**；浏览器不支持 H.264 编码时自动降级 `MediaRecorder` + `captureStream` 产 WebM，并在状态行说明「已降级」。两条都不支持会明确报错，不会产出坏文件；WebCodecs 声明支持但中途失败时（不同环境对 canvas → VideoFrame 的支持有差异）会自动退回录制模式再试一次。
- **码率**：`宽 × 高 × 帧率 × 0.07`（720p24 ≈ 1.5Mbps，3 秒约 600KB）；导出后状态行会报实际体积，超过 4MB 会提醒改用「下载」（节点 metadata 存的是 dataURL，base64 会让体积再涨约 1/3，会和工程一起存进浏览器本地库）。
- **帧数上限 240**（= 8s@30fps）：超了会拒绝并让你缩短时长或降帧率，避免把标签页拖死。
- **编码中可取消**；关窗会自动取消。渲染走一次性离屏视口，编码结束立即释放 WebGL 上下文。
- 一帧都不落盘：像素从 WebGL canvas 直接进编码器（不像图片导出那样先转 JPEG）。

## 产物与落到哪个槽位

| 按钮 | 产出 | 接到哪 |
| --- | --- | --- |
| 导出当前机位 → 参考图 | 1 个图片节点（当前机位画面） | 参考图槽位（`ref_image`），可直接接图生图 |
| 导出机位首尾帧 | 2 个图片节点（第 1 个机位=首帧、最后一个=尾帧） | 下游第一个视频节点的 `first_frame` / `last_frame`（显式槽位，与连线先后无关） |
| 导出多视图 → 参考图组 | 3 个图片节点（左前 / 正面 / 俯视）+ 一个折叠分组 | 参考图槽位（`ref_image_01..03`） |
| 生成运镜提示词 | 1 个文本节点（场景关系 + **对象关系** + **构图占比** + 机位 + 运镜，中/英可切） | 喂给视频模型；想更专业可以再用画布里的「视频提示词」技能润色一次 |

导出的图片节点与视频节点都按宿主约定**缩到最大边 420**（和宿主的抽帧/生成结果一致），真实分辨率写在节点 metadata 的 `naturalWidth / naturalHeight` 里 —— 所以画布上不会一次铺出一大片 1280/1920 宽的大节点。

提示词里的「关系」段会写清一对物体之间的**方位、距离与双方朝向**，横向对齐且一近一远时还会给「谁大致挡住谁」；「构图」段给每个主体**占画面高度**与偏左/居中/偏右。

没有下游视频节点时，「首尾帧」只出两张图并提示手动接 —— 不猜落点。
卡片上也留了「导出当前机位」与「运镜提示词」两个快捷动作：它们不打开大窗口，而是临时建一个离屏视口渲染完立刻释放。

## 怎么用

1. 新建「3D 导演台」节点（底部工具栏 → 扩展节点）。
2. 双击卡片进大窗口。
3. `+ 人物` / `+ 道具` 加占位体（低面数人形 / 方块），或 `导入 glb` 换真模型（存插件私有存储，刷新后自动装回）。
4. 在视口里拖拽摆位，或右侧用滑块/机位预设（过肩 / 正打 / 俯视 / 全景 + 适应全部）。
5. **放置机位的推荐流程**（也是唯一能看到相机的方式）：机位区点 **「看全场（自由视角）」** → 在外部视角里用「机位」滑块（方位角 / 仰角 / 距离 / 视线高度 / 焦距）把机位挪到位，**场景里的相机元素会跟着动**，你能一边看一边调 → 点 **「+ 记录当前机位」**，这台相机就留在场景里了 → 再调再记，直到记够。记完点「回到当前机位」回到镜头里。
6. 场景里**点任意一台相机元素**即选中它并切到外面的上帝视角（方便一边看全场一边布局）；**直接拖动相机元素**就能改那台机位（在地面上拖，自动换算方位角与距离，松手即保存）。想把镜头切到某台机位（之后记录机位 / 播放 / 导出都从它开始）点列表行里的 **「切到」**。
7. 摆好人物与机位后按上表导出。Esc 关闭大窗口。（想更复杂的运镜就多记几个，最多 8 个：第 1 个是首帧、最后一个是尾帧），然后按上表导出。Esc 关闭大窗口。

## 一句话搭场景（「预演搭建」技能）

不想自己挑模板、加素材、调机位？在**文本节点**里写一句画面描述，把「执行者」选成**本地 Agent**、技能选「**预演搭建**」，点执行：

- Agent 先挑最接近的**内置场景模板**当骨架，再按描述覆盖人物 / 道具 / 环境、灯光、当前机位、关键帧机位与人物走位（不要从零拼坐标）；
- 优先用内置素材而不是裸占位体；有人物走动就记走位点（走位与镜头共用同一条时间轴）；
- 最后导出一张**当前机位参考图**落在导演台节点旁边 —— 马上能看到这一帧；
- 之后打开大窗口继续微调，套错/改错可以用大窗口的撤销回退（见下）。

它和「命令通道」是同一套能力的两种用法：技能负责"读懂描述、决定搭什么"，插件负责"执行"。

## 命令通道（Agent / 脚本直接驱动）

插件不用被"点"也能干活：任何接了 MCP 的客户端在节点 metadata 上写一条指令，插件在**卡片**上读取并执行（卡片常驻，大窗口开不开都能跑），执行完把命令 id 写回回执：

```jsonc
// 客户端写入
"directorStageCommand": { "id": "cmd-1", "type": "applyScene", "sceneId": "seaside-lookout" }
// 插件执行后写回（幂等：回执等于 id 就不再执行，节点重挂载也不会重复跑）
"directorStageCommandAck": "cmd-1"
```

| type | 参数 | 行为 |
| --- | --- | --- |
| `applyScene` | `sceneId` | 套用内置场景模板（重建物体 / 机位 / 走位 / 运镜 / 灯光，保留导出偏好） |
| `setLighting` | `lighting` | 切灯光预设：`day` / `night` / `indoor` / `backlit` |
| `export` | `mode`: `prompt` / `current` / `firstLast` / `multiView` / `video` | 让插件执行导出（提示词 → 文本节点、当前机位 → 图片节点、首尾帧、多视图、运镜视频），复用卡片的离屏导出通路 |

- **模板数据不复制到客户端**：只传 `sceneId`，插件自己展开；Agent 侧对应 `canvas_director_stage` 的 `sceneId` 与 `exportMode`。
- **幂等**：执行是异步的（导出要渲染），执行中再收到同 id 的命令不重复执行，期间卡片置忙。
- **失败不静默**：未知 / 非法命令只写回执不报错（否则会永远重试），导出失败的原因写在卡片状态行。
- 可以全自动串起来：新建导演台 → `sceneId` 套模板 → 改几个物体 → `exportMode: prompt` 拿提示词 → `exportMode: video` 出预演视频，全程不用人点。

## 自检（搭完自己发现问题）

「运镜预演」区多了一行**自检**：不用点任何按钮，回显这一镜的确定性问题 —— 主体是否出画、占画面高度是否过小 / 过大、机位是否几乎贴着主体、两个物体是否重叠、走位过程是否出画（带时间点）。`✗` 是要修的，`⚠` 只是提醒；走位出画单独一行（避免重复）。

Agent / 脚本走**命令通道**拿同一份结论：写一条 `check` 指令（Agent 工具里就是 `canvas_director_stage({ nodeId, check: true })`），插件算完把报告写回节点 metadata 的 `directorStageCheck`：

```jsonc
"directorStageCheck": { "commandId": "cmd-1", "ok": false, "subjects": 2, "shots": 2, "moving": true,
  "issues": [{ "level": "error", "code": "out-of-frame", "text": "当前机位下「女主」横向出画 …" }],
  "text": "自检：2 个主体 · 2 个机位 · 有走位\n✗ …" }
```

- 自检是**纯计算**（不渲染），所以是同步的，也不依赖 WebGL；卡片、编辑器、Agent 读回用的是同一份实现。
- 判定是**近似几何**（按主体中心与视场角比），只用来抓明显问题，不承诺精确裁切。
- 环境类不算主体（与提示词口径一致）；场景为空时只报一条「没有主体」，不刷屏。

## 撤销

大窗口里画布的快捷键是被**有意忽略**的（模态带 `data-canvas-shortcuts-ignore`），所以插件自己接管撤销：

- 标题栏「**撤销 (⌘Z)**」按钮，或窗口内直接按 **Ctrl+Z / ⌘Z**；最多回退 20 步，栈空时按钮置灰。
- 连续拖动滑块按 400ms 合并成一步，避免"一步一变"。
- 只回退**场景状态**（物体 / 机位 / 走位 / 运镜 / 灯光），导出偏好不动 —— 与"套模板保留导出偏好"同一口径。
- 撤销栈只在大窗口会话内有效（关窗即清空）；要跨会话回退就用画布自身的 Ctrl+Z。

## 构建

```bash
cd plugins/canvas/director-stage
npm install
npm run typecheck   # tsc --noEmit
npm run build       # esbuild → dist/director-stage.js，并同步到 web/public/plugins/ 与 index.json
npm run dev         # watch 模式，改完刷新画布即可
```

> `tsconfig.json` 里把 `react` 用 `paths` 映射到插件自己的 `node_modules/@types/react`：SDK 的 `.ts` 源码会被拉进本插件的编译程序，而它按「从自身目录往上找」的规则解析不到插件目录下的 `@types/react`，不映射就会出现一串 `TS7026`（JSX 元素隐式 any）+ `TS2307`。

## 启用

- 开发态：`web/public/plugins/index.json` 会列出本地产物，画布启动时自动发现，在「插件 → 本地插件」里启用即可（`web/public/plugins/` 已 gitignore，只对本机生效）。
- 分发：把 `dist/director-stage.js` 放到可访问的 URL，在「插件 → 从 URL 安装」里填地址。

## 注意事项（安全与体积）

- **插件没有沙箱**：启用后是与画布同源的任意 JS，能读画布数据、能发网络请求。只装自己信任的插件。
- **体积**：three.js 与 GLTFLoader **随插件打包**（产物约 770KB，minify 后），换来的是不依赖任何 CDN —— 内网访问不到 `esm.sh` / `jsdelivr` 时插件照样能用（本仓库其它插件是运行时从 `esm.sh` 动态拉的，内网环境会拉不到）。这是与 `plugins/canvas/README.md`「重依赖不要打进 bundle」约定的**有意偏离**，只为了这个插件能离线跑；要发布到官方注册表前需要重新权衡。
- **WebGL 上下文**：只有打开大窗口时占用一个，关闭即释放；卡片不占。
- **性能**：视口静止时不跑渲染循环，只在交互与导出后渲染一帧；`pixelRatio` 封顶 2。
- **持久化**：物体列表、机位、机位 A/B 存在节点 metadata 里（轻量），卡片预览图存在 `metadata.previewContent`（360p JPEG）；导入的 glb 以 base64 存在**插件私有存储**里（按插件 id 命名空间隔离，跨节点共享，由「我的素材」管理），「我的模板」也在这里 —— 所以拖入大模型会占存储，注意用「导出素材库」备份。
- 导出的图片以 dataURL 写进图片节点 metadata，导出分辨率越高画布数据越大；日常用 720p + JPEG，只有当关键帧才用 1080p + PNG。
